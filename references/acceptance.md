# DiDi_OK 保真验收

此文件用于审查 Skill 或其生成结果，不用于每次普通生成。格式验证通过只说明文件可加载，不能说明生成行为合格。

## 完整模块

逐项确认输出是否具有以下模块；不相关模块可标记“不适用”，不得默默遗漏：

| 模块 | 验收证据 |
| --- | --- |
| 全局视觉合同 | 写实程度、画幅、摄影媒介感、单镜头或多镜头、整体气质 |
| 连续性锚点 | 人物、服装、道具、场景、光线和世界观中真正需要保持一致的属性 |
| 空间拓扑 | 前中后景、左右、内外、人物站位、共同观看物或遮挡边界 |
| 首帧 | 第一眼的机位、景别、主体、焦点与构图 |
| 连续因果链 | 起始状态、触发、动作中间态、反应、结果与收束 |
| 摄影机路径 | 摄影机从哪里到哪里、为何移动、怎样应对遮挡或突发事件 |
| 焦点行为 | 焦点落点、游移、失焦、再对焦与叙事对象的关系 |
| 表演潜台词 | 呼吸、眼神、停顿、局促动作、克制反应及反应先后 |
| 真实物理 | 尺度、材质、接触、受力、阻力、惯性、碰撞、形变和落点 |
| 尾帧 | 最终构图、视觉证据、人物关系或情绪落点 |
| 同期声 | 与空间、材质、距离和动作对应的现场声音 |
| BGM 声明 | 每条都必须单独、明确写出“无 BGM，无配乐！” |
| 失败防护 | 只禁止与当前镜头高度相关的故障 |

## 原案例强调重点

六个标准 Case 反复强调的不是固定题材，而是以下生成纪律：

1. **极度真实可信的实拍质感！** 真实来自操作者呼吸、自动对焦迟疑、曝光变化、材质磨损、重量与环境底噪。
2. **空间纪律必须可验证！** 例如镜头始终在人群背后、转场中必须同时看到新旧空间、人物不看镜头。
3. **关键动作必须具有中间态！** 抓取、滚动、爆裂、挥拳、后退均需写明接触、施力、惯性与结果。
4. **摄影机必须像现场的人！** 它会踮脚、避让、寻找视线、晚半拍回摇、短暂失焦后重新对焦，而不是全知视角。
5. **表演必须有潜台词与时差！** 角色以搓手、轻咳、眼神游移、强颜欢笑、僵住或后退表达信息，不全员同步反应。
6. **声音必须证明空间！** 同期声对应具体材质、距离与环境；每条都必须明确“无 BGM，无配乐！”。
7. **硬约束必须写得足够硬！** 使用“严格”“必须”“始终”“全程”“绝不”等词，并用感叹号强调最容易失败的关键要求。

## 禁止擅自增加

- 用户未指定时，不增加具体秒数、时间码或建议时长。
- 不把某一 Case 的 16:9、一镜到底、陌生面孔、糖果、无国家信息等局部设定误当成所有任务的固定要求。
- 不为了“电影感”擅自增加雨夜、青橙调色、慢动作、胶片颗粒、特定摄影机或镜头型号。
- 必须根据主题充分补全人物年龄、外貌、服装、身份、空间、材质、光线、动作、台词、微表演、声音与必要剧情细节，使画面具体、完整、可拍摄。
- 补充内容必须服务用户主题和镜头执行，不得机械套用 Candy 的人物、道具或世界观；唯一绝对不能擅自增加的是时长、秒数和时间码。

## 前向测试

用一个只有人物、地点和事件的一句话请求测试。合格输出应做到：

- 不自设时长和时间码。
- 不解释方法，直接形成连续自然段 Prompt。
- 至少明确首帧、空间关系、摄影机路线、动作因果、焦点、物理/表演、尾帧、同期声、BGM 与相关禁止项。
- 关键硬约束沿用原案例的语言强度，但不照搬 Candy 人物、对白或世界观。
- 逐项列出模型为可执行性补足了什么；若用户只要 Prompt，则在内部检查，不把分析混入交付。
